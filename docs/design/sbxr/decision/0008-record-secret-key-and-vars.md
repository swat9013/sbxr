# 0008. 作成時の宣言に、配線した secret の key と vars を記録する

- Status: Accepted
- Date: 2026-09-27
- 覆す条件: secret 定義の key や vars が VM に焼かれなくなったとき（create 以外で VM の環境変数や sandbox スコープの secret を置き直せるようになったとき）

## 決定

- 作成時の宣言の配線した secret に、secret 定義の `key`（secret ファイルのキー）と `vars`（秘密でない付随値）を足す。drift はこの 2 つも比べる
- secret の値（secret ファイルの中身）は宣言ではないので記録せず、比べない
- v0.1.0 の記録（配線した secret に `key` が無いもの）は、その secret の `key` と `vars` を比べない。比べなかったことを「作成時に記録していないので比べていない」と注記する
- 配線の結果（`internal/secret`）が、VM の環境変数・実行基盤に置く secret・作成時の宣言に残す形の 3 つを出す。create と drift は field を選ばない

## 根拠

- `vars` は create で VM の環境変数へ焼かれ、`key` は sandbox スコープの secret に置く値を決める。どちらも作り直さないと既存の VM に届かないので、drift の定義（既存の sandbox VM が取り込まない差）に当たる
- 記録に無かったのは、1 つの配線の判断を 3 つの形へ手で写していたため。形を出す場所を配線の結果 1 か所にすれば、写し漏れが起きない
- `key` は secret 定義の検証で空にならない。記録の `key` が空なら v0.1.0 の記録だと判定でき、記録の版を別に持たなくて済む
- v0.1.0 の記録を比べると、宣言を変えていない VM にも差が出て、作り直しを強いる（偽の drift）。状態ディレクトリは足すだけにする（ADR 0006 の改訂は #50）

## 却下した代替案

- secret の値の hash を記録して比べる: 値は secret ファイルで回す前提で、値の更新は sbx の sandbox スコープの secret を置き直す別の操作に属する。宣言の差（drift）ではない
- 作成時の宣言に記録の版（schema version）を足す: `key` の有無で判定できる。版を足すと、版ごとの読み方という状態が増える
- v0.1.0 の記録の `key`・`vars` を空とみなして比べる: vars を持つ secret を配線した VM すべてに偽の drift が出る
