# 0006. egress 自己検証は VM 内から実際の通信で 1 往復ずつ行う

- Status: Accepted
- Date: 2026-09-26
- 覆す条件: [system.md の未実測の前提](../system.md#未実測の前提) 6 が成り立たないとき

## 決定

create の最後（boot の後）に、VM 内から次の 2 つを確かめる。

- **許可先に届く**: 実効の許可集合（global rule の期待集合 ∪ sandbox スコープ rule の宛先）から、glob を含まない `:443` の宛先を 1 つ決定的に選び、そこへ届くこと
- **許可外に届かない**: 固定の候補を順に見て、許可集合に一致しない最初の 1 つへ届かないこと

どちらかが失敗したら、VM を残す段の失敗として create を止める。作成時の宣言は、これが通った後にだけ書く。

## 根拠

- #12 の範囲のとおり、VM 内から確かめる
- `sbx policy check network` は host 側で policy の評価器を見るだけで、VM の通信が実際に proxy を通ることは確かめない

## 却下した代替案

- `sbx policy check network` で確かめる: 上の理由で、確かめたいことの半分しか見ない
- 宣言したすべての宛先を確かめる: create の時間と、外部への通信が宛先の数だけ増える
