# 0019. doctor は sbx の版を、対応する下限と実測済みの上限に照らして検査する

- Status: Accepted
- Date: 2026-11-16

## 決定

- doctor の環境の検査に、項目「sbx の版」を足す
  - 下限（decision/0018）より旧い: fail にし、sbx の更新を示す
  - 実測済みの上限より新しい: ok のまま、実測済みの範囲の外であることを注記する
  - 版を読めない: fail にする
- 実測済みの上限はコードの定数 1 つで持ち、実 sbx で create から destroy までの 1 周を通した版へ上げる
- create と plan は版を検査しない

## 根拠

- sbx の変更で sbxr が壊れたのは 2 回目である（v0.45.1 → v0.48.0 の 4 点、v0.51.0 の kit の混在の拒否）。2 回目は、doctor が ok 9 / fail 0 のまま create が失敗した
- 機械の検査は、人が release notes を見続けることに頼らない

## 却下した代替案

- 監視用の issue を置き、人が sbx の release notes を見る（#95 の案）: 見る人の注意が切れると、同じ壊れ方を通す
- 実測済みの上限より新しい版を fail にする: sbx を上げるたびに sbxr の release を待つことになる。v0.49〜v0.50 のように壊れない版のほうが多い
- create でも版を検査する: create の失敗は sbx の error をそのまま示す。同じ検査を 2 か所に持たない

## 見直し条件

置かない（注記が読まれたかと、版のずれで create が失敗したかは、実行の記録から数えられない）
