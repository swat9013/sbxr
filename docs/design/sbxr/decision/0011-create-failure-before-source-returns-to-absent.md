# 0011. 出所を記録する前の create の失敗は、書きかけを消して未作成に戻る

- Status: Accepted
- Date: 2026-09-28
- 覆す条件: 出所より前に、sbx の側へ何かを置く段（secret・VM・rule）が入ったとき（状態ディレクトリを消すと、destroy が片付けに使う定義が失われる）

## 決定

- create が、状態ディレクトリに出所を記録する前に失敗したら、書きかけの状態ディレクトリと git URL の cache clone を消し、未作成に戻る
  - 出所より前の段は、状態ディレクトリを作る・実行基盤の定義を書く・作成の最初の記録を書く、の 3 つ
  - 確認関門より前の失敗と、確認関門で断られたときも同じく、cache clone を消す（状態ディレクトリはまだ無い）
- 出所を記録した後の失敗は、状態ディレクトリを残す。作成途中になり、destroy で片付ける
- 片付けは lifecycle module が 1 回の create の内側で行う。「状態ディレクトリを書くところまで進んだか」を呼び出し側へ返さない

## 根拠

- 出所は、状態ディレクトリが sbxr の管理下にある印を兼ねる。sbxr は、出所の無い状態ディレクトリを未作成と読む。そこへ destroy を案内しても「無い」で止まり、git URL の cache clone も消えない。この決定の前の実装 (v0.1.0) は、この状態を「作った」扱いにして destroy を案内していた
- 出所より前の段は、sbx の側に何も置いていない（sandbox スコープの secret は VM の作成で置く）。状態ディレクトリを消しても、片付け損ねるものが無い
- 状態ディレクトリの書き込み順（定義 → 作成の最初の記録 → 出所）は ADR 0006 と decision/0009 が決めている。出所の有無 1 つで、消してよいかが決まる

## 却下した代替案

- 出所を最初に書く: 定義を書けないと、destroy が定義の無い状態ディレクトリで詰む（ADR 0006 の実測）
- 出所の無い状態ディレクトリも destroy で片付けられるようにする: 出所の無い状態ディレクトリは管理下の印を持たないので、destroy が同じ名前の管理外の VM に触れる経路ができる
- 書きかけを残し、次の create で上書きする: git URL の cache clone は次の create まで残る。次の create が来なければ、利用者から見えない clone が残り続ける
