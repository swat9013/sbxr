# 0010. 停止中の VM への stop は、herdr machine を無効にしてから「止まっている」と返す

- Status: Accepted
- Date: 2026-09-28
- 覆す条件: herdr が、無効にしていない machine の VM を繋ぎ直して起こさなくなったとき（UC3 の成功保証が herdr の無効化を要らなくなったとき）

## 決定

- 停止中（作成済み・停止）の VM への stop は、herdr 連携を有効にして作った VM なら herdr machine を無効にし、VM には触れずに「止まっている」と返す
  - 無効にしたなら、起動し直した後に有効に戻すコマンドを示す（稼働中の VM の stop と同じ）
  - host に herdr が無ければ止まる（UC3 の 3b と同じ）
  - 登録が無ければ警告し、利用者が既に無効にしていればそのままにして、「止まっている」と返す
- 作成途中・停止の VM への stop は、`sbx stop` を呼ばずに「止まっている」と返す。herdr machine には触れない
- 作成途中・稼働の VM への stop は、稼働中の VM と同じく herdr machine を無効にしてから止める（作成途中の VM の machine は未登録だが、同じ名前の前の VM の解除に失敗した登録が、有効なまま残りうる）
- 状態を読んでから振る舞いを選ぶ。この決定の前の実装 (v0.1.0) は、状態を見ずに herdr machine の無効化と `sbx stop` を走らせていた

## 根拠

- UC3 の成功保証は「VM が止まり、herdr 連携の VM なら herdr machine が無効になっている（herdr が VM を起こし直さない）」。外部停止（`sbx stop`）の後は、VM は止まっていても machine は有効のまま残る（状態機械の `Running --> Stopped : 外部停止`）。ここで stop が「止まっている」とだけ返すと、herdr が繋ぎ直して VM を起こしうる状態を、成功として利用者に返すことになる
- 停止中の VM に `sbx stop` を呼んでも状態は変わらない。呼ばないので、使用中の session を切る心配（system.md）も、止め直しの失敗も起きない
- 作成途中の VM は herdr machine を登録する前に止まっている（登録は作成時の宣言の後）。無効にするものが無い

## 却下した代替案

- 停止中の VM への stop は何もせずに「止まっている」と返す: 外部停止の後に herdr machine が有効のまま残り、UC3 の成功保証を破る
- 状態を見ずに、今どおり無効化と `sbx stop` を走らせる: 作成途中で VM が無いときも `sbx stop` を呼んで失敗する。状態機械の「止まっている」と食い違う
