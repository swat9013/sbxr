# 0035. 既に止まっている作成途中の VM への `sbxr stop` も、`sbxr destroy` を案内する

- Status: Accepted
- Date: 2026-11-19

## 決定

- 作成途中で既に止まっている VM（VM が無い場合を含む）への `sbxr stop` は、VM に触れずに「止まっている」と示し、続けて `sbxr destroy <repo>` で片付けてから `sbxr create <repo>` で作る手順を示す（UC3 の 2c）
- herdr machine には今までどおり触れない（作成途中の VM の herdr machine は登録前である）
- 作成途中の VM への stop の案内は、VM が稼働していたとき（decision/0029）も止まっていたときも、「止めた」「止まっている」の行の後に出す
- herdr machine を無効にしたことを示す行は、今までどおり「止めた」の行より前に出す。この行は次の操作の案内でなく、行った操作の記録である
- 作成済みの VM への stop の表示は変えない（UC3 の 4b を含む。作成済みの VM で `sbxr start` を添える herdr の行の位置も変えない）

## 根拠

- 作成途中の VM に sbxr が勧める操作は destroy だけである（decision/0025）。勧める操作は VM が作成途中かで決まり、stop の前に VM が動いていたかでは変わらない。decision/0029 は稼働中の場合だけを決め、既に止まっている場合は何も案内しなかった
- create に失敗して作成途中・停止になった VM に stop を打った利用者は、次に打つコマンドが見えず、`sbxr start` を試して拒まれうる（UC10 の 2b）
- 案内は VM の状態を示した後に読む次の操作なので、状態の行より前に出ると、何をした結果の案内かが読み取りにくい

## 却下した代替案

- 既に止まっている作成途中の VM への stop を拒否（非 0 で終了）にして destroy を促す: 止まっている VM への stop は、作成済みの VM（4b）と同じく成功として終える。作成途中かどうかで stop の終了 code を変えると、止まっていることを確かめるためだけの stop が失敗に見える
- 案内を出さずに今のまま「止まっている」とだけ示す: 作成途中の VM は destroy しないと create も start も通らないのに、止まっている場合だけ次に打つコマンドが利用者に見えない（decision/0029 が稼働中の場合に退けたのと同じ理由）。案内を出すことは人が決めた（#165）

## 見直し条件

置かない（案内の文言の決定で、実行の記録から測れる量が無い）
