# 0026. 作り直しを 1 コマンド `sbxr recreate` にする

- Status: Accepted
- Date: 2026-11-19

## 決定

- `sbxr recreate <repo>` を足す。sbxr が作った VM（稼働中・停止中・作成途中・VM 消失）を、止めて撤去し、現在の宣言から作り直す
- 確認プロンプトは 1 回にする。作る内容と、VM 内の commit と変更が失われることを一緒に示す
- 未作成の VM には拒否して create を促す。管理外・別出所には触らない
- 状態機械には新しいイベントを足さない。recreate は stop → destroy → create を続けて起こす。途中で失敗したら、そこまでのイベントが起きた状態で止まる
- 宣言の変更を sbxr が自動で反映することはしない。作り直すのは、利用者が recreate を打ったときだけ

## 根拠

- VM は作った後に宣言を取り込まないので、宣言を変えたら作り直す（decision/0023）。その作り直しが stop → destroy → create の 3 コマンドと 2 回の確認だった
- 1 コマンドにしない理由は「未 push の作業をどう扱うかの判断を利用者の手に残す」だった（usecases.md の UC7 の却下）。作業の保全を目的から外したので、この理由は無くなった

## 却下した代替案

- `sbxr create --replace`: create に「作成済みなら drift を報告する」と「作成済みなら消して作る」の 2 つの意味が付く
- drift を見つけたら自動で作り直す: 利用者の確認なしに VM 内の変更が失われる

## 見直し条件

置かない（コマンドの有無の決定で、実行の記録から測れる量が無い）
