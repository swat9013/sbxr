# 0027. create と start は、終わりに VM の中で agent と Docker が使えることを確かめる

- Status: Accepted
- Date: 2026-11-19

## 決定

- create と start の成功保証に、次の 3 つを足す
  - VM の中で agent（Claude Code）を起動できる
  - VM の中で Docker を使える
  - herdr 連携を有効にして作った VM では、herdr の pane で agent を起動できる
- sbxr は create と start の終わりに、VM の中でこの 3 つを確かめる。成り立たなければ失敗として止まる
  - create（agent と Docker）: 作成時の宣言を書く前に確かめる。成り立たなければ、VM の中の段の失敗と同じく、VM を残して止まる（作成時の宣言を書かない）
  - create（herdr の pane）: herdr machine の登録の後に確かめる。成り立たなければ、VM と登録は作成済みとして残し、成り立たなかった項目を示して非 0 で終える（登録の失敗と同じ扱い）
  - start: VM は稼働中のまま、成り立たなかった項目を示して非 0 で終える
- VM の中の構成は境界の外のままにする（system.md）。境界の上で保証するのは、この 3 つだけである
- sbxr の外での起動（外部起動）では確かめない

## 根拠

- 目的の「VM の中で開発できる」（decision/0023）を、設計のどの成功保証も書いていなかった。Docker の記述は default の egress の理由だけだった
- 起動し直した VM の herdr の pane で agent が見つからない不具合（#87）は、create の経路では起きず、起こし直しの経路でだけ起きた。確かめる段が無いので、sbxr は気付けなかった

## 却下した代替案

- 成功保証に書くだけで確かめない: 実行基盤か herdr の更新で成り立たなくなったとき、利用者が VM に入るまで分からない
- 確かめる内容を利用者が boot に書く: 宣言 1 枚ごとに同じ確認を書くことになり、手軽に反する

## 見直し条件

置かない（保証の有無の決定で、実行の記録から測れる量が無い）
